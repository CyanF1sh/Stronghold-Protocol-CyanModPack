# ⚠ 两个整活 Mod 的版本过时提醒

本仓里有 **2 个 Mod** 是**按归档原样**发布的，**没有适配 0.2.5**：

| Mod | 版本 | `mod.json` 的 `gameVersion` | 当前游戏版本 |
|---|---|---|---|
| `cyanfish.dj-models` | **v1.6.1** | **0.2.4** | **0.2.5** |
| `cyanfish.dj-bgm` | **v1.0.1** | **0.2.4** | **0.2.5** |

> 原归档就是这样：这两个 Mod 当年是在 **0.2.4** 上做的。服主裁定「按归档原样发布」，
> 所以本仓**没有**改它们的 `gameVersion`，也**没有**改它们的一行业务代码。

## 装到 0.2.5 上会发生什么（预期症状，**不是坏了**）

装载器对 `gameVersion` 做**严格相等**校验（平台代码见覆盖层的 `server/mods/loader.js`，
游戏版本读取自宿主 `package.json` 的 `version`）。在 0.2.5 上：

1. 这两个 Mod **仍然出现在 `/mods` 列表里**（可见、可查）；
2. 各自**带一行错误**：
   ```
   gameVersion=0.2.4 与当前游戏版本 0.2.5 不一致
   ```
3. 状态被标为 **`skipped: true`** ⇒ **不装载**（一个钩子都不注册、不产生任何效果）；
4. **不会崩服**，其它 Mod 照常工作、其它玩家的对局不受影响。

`node tools/mod.mjs validate` 也会对它们各报一条同样的错误，所以整批校验**以退出码 1 结束**：

```
✗ cyanfish.dj-bgm  (0 ops)
    错误: gameVersion=0.2.4 与当前游戏版本 0.2.5 不一致
✗ cyanfish.dj-models  (0 ops)
    错误: gameVersion=0.2.4 与当前游戏版本 0.2.5 不一致

2/21 个 Mod 校验未通过  （另有 1 个 Mod 有提示，不影响通过）
```

★ **这就是预期输出**。看到 `2/21 未通过` 不等于装坏了 —— 它正好是这两个 Mod 的版本门槛在起作用。

## 想用它们怎么办

| 办法 | 说明 |
|---|---|
| **等作者更新** | 作者后续会适配；两个 Mod 目录**自足、零跨目录依赖**，更新时只动自己的目录 |
| **当源码参考读** | 这是最稳的用法：`cyanfish.dj-models` 演示了「只读游戏交给客户端的两个全局抓手」的纯视觉整活写法，`cyanfish.dj-bgm` 演示了「覆盖官方 BGM 声道 + 设置栏位」的写法 |
| **自己改 `gameVersion` 试** | 把 `mod.json` 的 `gameVersion` 改成 `"0.2.5"` 再重启 ⇒ 能装载，但 **0.2.4 → 0.2.5 之间有基座改动，不保证效果**；出问题就改回 `"0.2.4"` |

## 另外：这两个 Mod 里与「素材」有关的事

- `cyanfish.dj-models`：**零素材**。那个梗只用**文字描述**实现，不拷贝任何图片 / 音频。
- `cyanfish.dj-bgm`：原归档里那首 4.41 MB 的第三方曲子**没有取得权利人授权** ⇒ **本仓不随包发布**。
  目录 `assets/bgm/` 保留着，里面只有一份说明；曲目是**数据驱动**的，代码不依赖任何一首具体的歌。
  放自己的曲子见 `mods/cyanfish.dj-bgm/OUTDATED.md`。
