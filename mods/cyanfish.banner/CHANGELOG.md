## 1.2.0 — 2026-10-12
- ★ **对局内也能看到**（服主口径：「对局中也要能看到」→「横幅公告可以做成**类似弹幕的从靠顶部的右侧飘过 +
  半透明 + 点击穿透**，这样就不用太考虑遮挡问题」）：宿主新开一条插槽 **`game.banners`**
  （`public/js/ui/extensions.js` 的 `UI_SLOTS.GAME_BANNERS`；落点 = `screens/game.js` 的 `.gm__hud` 直接子节点、
  紧跟官方顶栏 `<header class="gtop">` 之后），本 Mod 把**同一个** `Banner` 组件再注册一次进去 ⇒
  **同一份 `live.json`、同一个 `isActive()` 判据**（`client/plan.js` 的 `itemWindow`，没有第二套时间判断）、
  同一套 `.sp-bn*` 样式与同一段轮询（两个槽位分属两个屏幕，同一时刻只有一个挂载 ⇒ 只有一个轮询在跑）。
- 对局内形态 = **弹幕**：落在 `top:1.0rem` 那条 0.34rem 高的通道（官方 `.ticker` 用的位置），
  **自右向左横穿整屏、单次 9 秒**，**每 45 秒再飘一次**（中途进局 / 中途发布的人都看得到）。
  整层 `pointer-events: none !important`（压过宿主 `.gm__hud > *` 的 auto）⇒ **点击/拖拽全穿透**。
- **半透明**：行 `opacity: .78` + 底衬 `rgba(6,9,8,.55)`；文字加一层极轻的 `text-shadow` 描边
  （只加描边、不加背景块 —— 在战场画面上读得清，又不增加太多视觉重量）。
- **为什么不常驻**（真机实测量出来的）：对局界面全是绝对定位，顶栏 0~0.82rem、官方 ticker 1.0~1.3rem、
  盟约带从 1.36rem 起、官方「回合」框在顶栏正中 —— 任何**常驻**横幅都必然**长期**压住「回合」框或盟约带。
  弹幕把遮挡变成**瞬时**的：真机实测任一固定点（「回合框」中心）单次只被覆盖 **1912~1932 ms**（< 2 秒）。
- **无障碍**：`@media (prefers-reduced-motion: reduce)` 成立时**不位移**（原地静态短显、同样的 9 秒）；
  另外按 `p` 可以就地停住 / 继续（`animation-play-state: paused`），方便停下来读。
- 每一轮**显式重启动画**（摘 `animation` → 强制回流 → 挂回）：Preact 在"内容没变"时不碰 DOM，
  CSS 动画跑完一次就停在终态 ⇒ 只靠 `setState` **不会**再飘（本工序真机实测确认过，已修）。
- 宿主**没有为它写任何 CSS**（通道、半透明、动画、点击穿透全在本 Mod 的 `client/style.js`）；
  首页那一条 `lobby.banners` 仍然是一条静态行（形态与判据**逐字节未变**）。
- 老宿主（没有 `game.banners`）⇒ 只注册首页那一条并留一条 warn，不报错、不影响首页横幅。
- 撤回到「一条都没有」时，对局内的 `.gm__hud` 子节点与加这条插槽之前**逐字节相同**（空插槽零节点）。

## 1.1.0 — 2026-10-11
- ★ 「结束时间」换成「**持续时间**」（服主口径：横幅公告不应使用结束时间，而是持续时间 —— 临时的提醒内容一般不会持续太久）。
  管理页那一栏现在是一个下拉：30 分钟 / 2 小时 / 6 小时 / 1 天（默认）/ 3 天 / 不过期 / 自定义分钟数（1 ~ 43200）。
  ★ 病因见 `<开发期报告>/75-banner-duration.md` B 节：`datetime-local` 一打开就带「现在」⇒ 服主那条公告的
  结束时间 = 发布的那一分钟，**落盘即过期**，客户端一条都不渲染（"发了看不见"）。
- 数据模型：条目写 `from`（开始时刻）+ **`mins`（持续多少分钟）**，显示判断 = `now < from + mins * 60000`；
  **老数据不变坏** —— `mins` 缺失时原样按旧的 `to`（绝对结束时刻）判断，两条路都在 `client/plan.js` 的 `itemWindow()` 里。
- 反向兼容：管理页写 `mins` 的同时**镜像**一份 `to = from + mins*60000` ⇒ 还没升级到 1.1.0 的旧客户端（例如尚未重推的实例）
  照样按同一个截止时刻到点消失；`mins` 一旦存在就是唯一真相（改时长不用去改 `to`）。
- 管理页：`「开始」填在过去`与`选了自定义却没填分钟数`两条会被当场拦下并说明（前者的下场正是一发布就过期）。
- 边界（逐条真机验过）：`mins` 缺失 / 0 / 负数 / 非数字 ⇒ 当「不过期」处理（**显示**，绝不静默消失）；`mins` 超 43200 ⇒ 夹到 30 天；`to <= from` 写反 ⇒ 按「不限时间」处理。
- 面板上的条目现在显示「持续 30 分钟（至 2026-10-11 22:35）」；只有旧 `to` 的条目标一枚「旧格式（结束时刻）」，服主可以按需重发一次。
