# cyanfish.banner — 实时横幅公告（L4 + 一条数据补丁）

给服务器加一条**常驻横幅**：玩家打开首页（选择模拟协议）时，在顶栏正下方看到服主发布的通知；
**对局内**（1.2.0 起）也在顶栏正下方同一位置显示**同一条**通知 —— 所以「服务器 22:00 要重启」
这种话，正在打的人同样看得见。
典型用途是「服务器 22:00 要重启」「今晚测试服开放」这类**几分钟内要通知到人**的事。

## 服主怎么发布

1. 打开 **Mod 管理页**（游戏服务的 `/admin`，需要 `SP_ADMIN_TOKEN`）；
2. 找到「**实时横幅公告**」一栏，填「横幅正文」（可选：级别 / 开始时间 / **持续时间** / 链接 / 条目 id）；
3. 点「**发布 / 覆盖**」。

**持续时间**（服主口径：横幅公告不应使用「结束时间」，而是「持续时间」—— 临时的提醒内容一般不会持续太久）：
一个下拉，常用档 **30 分钟 / 2 小时 / 6 小时 / 1 天（默认）/ 3 天 / 不过期 / 自定义分钟数**（1 ~ 43200 = 30 天）。
显示判断是 `now < 开始时刻 + 持续时间`；「开始」留空 = 发布这一刻起算。★ 不用你算结束时刻 ——
`datetime-local` 那种选择器一打开就带「现在」，很容易写出一个**已经过去**的结束时间（1.1.0 之前就这么踩过一次：
公告落盘即过期，玩家端一条都看不见，见 `<开发期报告>/75-banner-duration.md` B 节）。

**发布即生效**：不需要「重载 Mod」、不需要重启、不影响正在进行的对局。玩家端每 20 秒读一次，
所以最迟 20 秒内出现；玩家刷新页面则立刻出现。到点后同样最迟 20 秒消失。

**撤回**：同栏的「**撤回全部**」，或对某一条点「删除」。玩家端同样在 20 秒内消失。

## 它到底把东西写到哪

| 通道 | 位置 | 谁写 | 生效方式 |
|---|---|---|---|
| **实时文档** | `mods/cyanfish.banner/live.json` | 管理页 `POST /admin/api/live?id=cyanfish.banner` | 玩家端轮询 `/mods/cyanfish.banner/live.json` |
| 数据补丁（常驻条目） | `mods/cyanfish.banner/data/config.json` 的 `banner.items` | 服主手改 | 合并进 `/data/config.json`，改完要「重载 Mod」 |

- 两路**并行显示**，**同 id 时实时文档赢**（`client/plan.js` 的 `mergeItems`）—— 所以「管理页就地改一条常驻公告」不会把它变成两条。
- `live.json` 是**本机运行态**（与 `<modsDir>/.state.json` 同类）：随包分发的是**空文档**（`{"items":[]}`），
  `tools/mod.mjs pack` 打包时**强制替换成空文档** ⇒ 新装一台服务器**不会**继承你这台服务器发布过的横幅。
  这也是它随包分发的原因：玩家端永远能 GET 到一个 200 的文件，不必为"还没发布过"写一条 404 分支，
  **控制台不会因为轮询刷 404**（真机实测见 `<开发期报告>/61-browser-probe.txt` 的 `[4]` 段）。
- 读取走的是宿主**已有**的 `/mods/` 静态挂载（整个 Mod 仓库是只读静态目录），**没有新增任何对外端点**；
  写入只有一条带令牌的管理端点（`server/admin.js` 的 `/admin/api/live`，通道契约见 docs/MODS.md **§4.14**）。

## 数据补丁（`banner` 段）

```json
{ "ops": [ { "op": "add", "path": "banner", "value": {
  "enabled": true,
  "pollSec": 20,
  "maxItems": 3,
  "items": [
    { "id": "welcome", "text": "本服为 6 人版，房主可在房间内自行调整人数", "level": "info",
      "from": null, "mins": null, "href": null }
  ]
} } ] }
```

| 键 | 含义 | 非法 / 缺省时 |
|---|---|---|
| `enabled` | 总开关。**显式 `false`** 才关（写坏了按开处理） | 开 |
| `pollSec` | 轮询间隔（秒），夹在 `5 ~ 300` | `20` |
| `maxItems` | 同屏最多显示几条（多出来的不显示），夹在 `1 ~ 5` | `3` |
| `items[]` | 条目数组，字段见下 | 空数组 ⇒ 一条也不显示 |

单条条目：`id`（缺省按正文算一个确定性 id）、`text`（**必填**，超 200 字截断）、
`level`（`info` / `warn` / `danger`，不认识的当 `info`）、`from`（开始时刻；毫秒数或可解析的日期字符串；
缺省 = 立即）、**`mins`**（**持续多少分钟**：1 ~ 43200，越界夹取；缺省 / 0 / 负数 / 非数字 = 不过期）、
`to`（**旧口径**：绝对结束时刻；只在 `mins` 缺失时生效 —— 1.0.0 的老数据照旧读，
**写反了（结束早于开始）按"不限"处理**，而不是让这条永远不出现）、`href`（只放行 `http/https`，其它一律丢弃）。

**两种时间写法怎么合到一起**（`client/plan.js` 的 `itemWindow()`，全库唯一一处）：

| 条目里有什么 | 实际展示时间窗 | 谁在用 |
|---|---|---|
| `from` + `mins` | `[from, from + mins × 60000]` | 1.1.0 起管理页写的；**`mins` 赢**，同 id 的 `to` 只是给老客户端的镜像，被忽略 |
| 只有 `to`（`from` 可有可无） | `[from?, to]`（与 1.0.0 逐值相同） | 服主 1.0.0 时期已经发过的数据、手写的数据补丁 |
| `mins` 有值但 `from` 缺失 | 当「不过期」处理 | 手写数据补丁写了一半 —— **宁可不过期，不可静默消失** |
| 什么都没有 | 一直显示 | 常驻公告 |

★ 反向兼容也留了：管理页写 `mins` 时**镜像**一份 `to = from + mins×60000` ⇒ **还没升级到 1.1.0 的旧客户端**
（例如尚未重推的实例）照样按同一个截止时刻到点消失 —— 面板与测试服的实测见
`<开发期报告>/75-banner-duration.md` A 节第 ⑥ 条。

## 边界（诚实登记）

- **首页与对局内都显示**（1.2.0 起）：首页那一条是**顶栏之下的静态行**（插槽 `lobby.banners`）；对局内那一条是**弹幕**（插槽 `game.banners`，从靠顶部右侧自右向左飘过、单次 9 秒、每 45 秒再飘一次、半透明 `.78`、**整层点击穿透**）。两处共用同一份 `live.json` 与同一个时间窗判据（`client/plan.js` 的 `itemWindow`）。★ **对局内这一条要与"发了看不见"分开**：服主 1.1.0 那次两处都没看见，首页那处的原因是**结束时间已过期**（上面那节），对局内那处是**从来就没做过**（宿主当时没有那条插槽；工序 75 的真机取证见 `<开发期报告>/75-banner-duration.md` B 节第 ⑥ 条）。
- **对局内为什么是弹幕而不是常驻横幅带**：对局界面全是绝对定位 —— 顶栏占 0~0.82rem、官方 ticker 占 1.0~1.3rem（那一条已经分给了它）、盟约带从 1.36rem 起、官方「回合」框在顶栏正中 ⇒ 任何**常驻**横幅都必然**长期**压住「回合」框或盟约带。弹幕把遮挡变成**瞬时**的：真机实测任一固定点单次只被覆盖 ≈1.9 秒，且点击全穿透 ⇒ 不打断任何操作。对局内只显示**最靠前的一条**（多的在首页那一条上显示）。
- **不是推送**：最迟 `pollSec` 秒（默认 20）才可见；页签隐藏时不轮询（切回来立刻补一次）。★ 同一时刻只有一个屏幕挂着横幅（首页 / 对局二选一）⇒ 也只有一个轮询在跑。
- **可以停下来读**：按 `p` 就地停住 / 继续弹幕；系统开了「减少动态效果」（`prefers-reduced-motion: reduce`）时不位移，改为原地静态短显同样的 9 秒。
- **时间基准是"发布这台机器的钟"**：`mins` 的锚点 `from` 由**管理页所在浏览器**在发布那一刻取 `Date.now()`，判断由**玩家浏览器**的钟做。两台机器的钟差多少，公告的起止就差多少（同一台服务器上通常 < 1 分钟，对 30 分钟起的时长无所谓）。服务器时钟不参与 —— 所以服务器换了时区也不影响已经发出去的公告。
- **单行截断**：横幅是一条带，过长的正文以省略号结束；鼠标悬浮能看到全文（原生 `title`，本 Mod 不画自有气泡，因此不违反 docs/MODS.md §4.12.2 的"两套框重合"禁令）。
- **`live.json` 没有历史**：它只有"现在是什么"。要留记录请写 `CHANGELOG.md`（面向版本）或用 `cyanfish.announce`（面向玩家时间线）。

## 零痕迹（不发布 / 不装这个 Mod）

- 没装 / 停用 ⇒ 该模块根本不会被 `extensions.js` import；
- 装了但没有任何条目 ⇒ 插槽组件返回 `null` ⇒ Preact **不产生任何节点**：首页 DOM 与加 `lobby.banners` 之前**逐字节相同**（`lobby.topbar` / `lobby.banners` 两条插槽的自证见 `<开发期报告>/61-announce-stats-and-audit.md`）；对局内的 `.gm__hud` 子节点与加 `game.banners` 之前**逐字节相同**（0.2.3 · 工序 77 的自证见 `<开发期报告>/77-inmatch-banner-and-token.md`）；
- 样式只在**真的要画一行**时才注入 `<head>`（幂等，按 id 判断）。

## 文件

| 文件 | 作用 |
|---|---|
| `mod.json` | 清单（`gameVersion` 必须与宿主 `package.json` 逐字符相同） |
| `data/config.json` | 唯一一条数据补丁：新增 `banner` 段（内容全在数据里，改内容不用改代码） |
| `client/plan.js` | 纯逻辑：清洗 / 合并 / 时间窗（`itemWindow`：持续时间与旧 `to` 两路）/ 夹取（可离线逐条断言，不碰 DOM） |
| `client/index.js` | 注册 `lobby.banners` + `game.banners` 两条插槽（同一个 `Banner` 组件）+ 轮询实时文档 + 渲染 |
| `client/style.js` | `.sp-bn*` 样式（首页对齐宿主 `.lobby-body`；对局内 `.sp-bn--game` 是弹幕通道 + 飘过动画 + 点击穿透） |
