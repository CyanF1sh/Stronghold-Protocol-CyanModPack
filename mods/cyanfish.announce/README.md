## 一、服主怎么改公告（唯一要动的文件）

```
mods/cyanfish.announce/data/config.json      ← 只改这里
```

```jsonc
{
  "ops": [
    { "op": "add", "path": "announce", "value": { "items": [
      {
        "id":    "welcome-2026-10",           // 必需 · 唯一 · 「看过没有」就是按它记的
        "title": "欢迎来到本服务器",            // 可选 · 卡片标题
        "body":  "第一行\n第二行",              // 必需 · 正文，\n 换行
        "date":  "2026-10-08",                // 可选 · 标题右侧的小字
        "level": "info"                       // 可选 · info | warn | danger，只影响左边框配色
      }
    ] } }
  ]
}
```

★ **这就是平台的「数据接缝」通道**（规范 §4.6：界面文案属于 `data/` 轴）—— 所以：

| 动作 | 做法 |
|---|---|
| 加一条公告 | 往 `items` 里加一个对象 |
| 改文案 / 修错别字 | 直接改 `body`，**玩家不会重新看到**（已读是按 `id` 记的） |
| 让老公告重新弹一次 | 换一个新的 `id`（惯用做法：`welcome-2026-10` → `welcome-2026-11`） |
| 下线一条公告 | 从 `items` 里删掉即可（已读记录会保留，将来同 id 加回来不会重弹） |
| 生效 | 管理页点**「重载」**（不重启进程），或重启服务；玩家侧刷新页面 |

★ 打包成 `.spmod` 分发时公告内容**不会丢**（`data/**` 在安装白名单里）。
★ 服务器端不认识 `announce` 这个键 —— 它只是被随 `config.json` 一起下发，所以**不装这个 Mod 的服务器下发的 config 与官方逐字节相同**。

## 二、玩家侧看到什么

1. 打开游戏页面（点击进入之前就会弹）→ 若存在未读公告，弹出一屏列表（可滚动），点「我知道了」关闭。
2. 关闭之后这些 `id` 被记进**该浏览器的** `localStorage`（键 `sp.pref.announce`，与 `sp.pref.skinvoice` 同款命名）。
3. 之后每次打开页面：还有没读过的 → 只弹那些；全都读过 → **什么都不弹**。
4. 想再看一遍：顶栏齿轮 → **「模组设置」→ 左栏「公告」**。那一栏列出服务器当前配置的**全部**公告，
   没看过的打「未读」角标，还有一个**「全部标记为已读」**按钮（不想让弹窗再出现时按一下即可）。

边界（如实写清）：

| 现象 | 原因 |
|---|---|
| 换浏览器 / 换设备 / 清缓存后会重新看到 | 已读记录在**浏览器**里，平台没有「跨设备玩家身份」这种概念，所以做不到真正做到「每人一次」 |
| 同一个浏览器开两个标签可能各弹一次 | 两个页面同时判定时都还是未读 |
| 关掉页面（没点按钮）就再打开还会弹 | 记账发生在**关闭弹窗之后**，故意如此 —— 否则「面板还没渲染完就崩」会把公告永久吞掉 |
| 隐私模式 / 无痕里可能每次都弹 | `localStorage` 不可用 ⇒ `writeSeen` 返回 false，退化成「没装」而不是报错 |

## 三、降级与零痕迹（规范 §1.3 约束 2）

| 情形 | 行为 |
|---|---|
| 数据里没有 `announce` 段 | 不弹、不注入样式 —— 页面与没装这个 Mod 时相同 |
| `announce` 不是对象 / `items` 不是数组 | 同上（`parseAnnouncements` 返回空） |
| 某一条缺 `id` 或 `body` 为空 | **只跳过那一条**，其余照常弹；控制台出一条 warn |
| 同一条 `id` 出现两次 | 只认第一条，第二个计入 `dropped` |
| `level` 写了个不认识的值 | 当 `info`（只影响配色） |
| `localStorage` 抛错（隐私模式 / 配额满） | 当作没有已读记录 ⇒ 公告照常弹，绝不抛 |
| 拿不到 `/mods`（静态托管 / 离线） | 客户端 Mod 根本不装载 ⇒ 没有公告，页面照常 |
| 没装 `cyanfish.mod-settings` | 栏位注册进共享注册表但**没人画出来**（`registry.host` 为 null）⇒ 公告照常弹，只是没有回看入口；不报错 |
| 回看栏位从未被打开 | 样式**惰性注入** ⇒ 连 `<style>` 都没有（全已读时与「没装」逐节点相同） |

⇒ 全项目的验收口径「**≤N 等价**」在这里的具体形式分两档（v1.1.0 起，因为有回看，这是设计如此）：

| 情形 | 具体表现 |
|---|---|
| **没有可用公告**（没配置 / 全写坏） | 真正的零痕迹：不注册栏位、不弹窗、不注入样式、不注册插槽 —— DOM 与没装时逐节点相同 |
| **有公告但全已读** | 不弹窗、不注入样式、不占插槽；但「模组设置」里会**多一个「公告」栏位**（回看入口，设计如此） |
