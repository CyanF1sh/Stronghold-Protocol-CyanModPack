# DJ 干员（朋友的酒）· `cyanfish.dj-models` v1.6.0

> 把 B 站『朋友的酒 DJ 版』那个 meme 搬进整场游戏：**容器每帧反复上下压缩（弹簧感）+ 绕竖直轴原地转圈**。
> 纯视觉、纯整活：**不写任何玩法数值、不改 `public/**`、不 import 宿主内部模块、不碰宿主的 DOM 结构与事件**。
>
> ★★ **v1.6.0 是服主在测试服实测后的两条修复。**
> 服主原话①：「当前测试服发现的新问题：**干员晕眩时渲染丢失 / 只渲染部分**。」
> 服主原话②：「**伤害数字水平旋转是应该做成能够完整的转圈，而非仅是限定角度晃动**。」
>
> **① 晕眩 / 强控期间绝不碰模型选择**（`client/frontback.js` 的 `'stun'` 分支）
> * **宿主的晕眩是什么**（读代码钉死，不猜）：`public/js/render/units.js:716-720` 的 `_baseFromAnim()` ——
>   `if (this.anim === ANIM.STUN || (this.flags & (UF.STUNNED | UF.FROZEN | UF.SLEEP))) return 'stun';`
>   ⇒ **晕眩 / 冻结 / 沉睡三者被宿主完全等同**；而 `public/js/render/spine.js:254-282` 的
>   `setBase('stun')` / `_enterStun()` 说明它只是一个**动画模式**（`mode = 'stun'`：有 begin 就先播它再 queue loop，
>   只有 loop 就 loop，**两样都没有就 `frozen = true` 把当前姿态冻住**）。
>   它**不改模型**：既不切 `/front/` `/back/`、也不改 `entryBack`（那是 `_wantsBack()` 的事）—— 与「用哪套骨架」正交。
> * **我们原来会干什么**：在强控期间照样按 `cos θ` 的符号调 `view.setDir()` ⇒ 触发宿主
>   `units.js:802 _syncModel()` → `_wantsBack() !== entryBack` → `_loadSpine()` → `_acquireSpine()`：
>   旧 SpineActor 立刻被 `_dropActor()` 销毁（`spineReady = false`、`actor = null`），新骨架**异步**建完才
>   重新 `spineReady = true` 并 `this.actor.setBase(this._baseFromAnim())`
>   ⇒ 这是**一次宿主完全没打算做的模型重建**，还正好插在"宿主把强控姿态冻住 / 正在播 stun 剪辑"的当中
>   （`swapT` 交叉淡入、`_updateImpostor` 的贴图路径、`spineReady === false` 那一段都在这条路上）。
> * **治法**：把这三位加进 `frontback.js` 的「绝不碰」名单（与「倒地 / 死亡 / 淡出」那条纪律**逐字同源**）——
>   期间**一个字节都不写**（不 `setDir`、不动 `dir` / `facing` / `visFacing` / `hasDir`），把模型选择完全留给宿主；
>   强控一结束，下一帧的 `step()` 照常按 `cos θ` 的符号重新对齐。
> * ★ **代价（如实记录）**：强控期间旋转照旧在转（`scale.x ∝ cos θ` 照旧写），所以这一小段时间里「正 / 背」
>   可能与 `cos θ` 的符号不一致（最多偏一个 ±90° 窗口）。这是**故意的**：宁可观感略有出入，
>   也不要在宿主冻结强控姿态的时候替它重建模型。
> * ★ **难度诚实**：服主自己说"晕眩比较难测" —— 本轮**未能在真机里自然造出晕眩**（尝试路径见报告 §①）。
>   这条是**防御性修复**：判据逐条来自上面那几个行号，单测（§H）覆盖了"强控期间 `setDir` 调用数 = 0 /
>   模型一次都不重建 / 强控一结束就重新对齐"，真机也用宿主自己的 `sync()` 打上晕眩逐帧取证，
>   但**未经真实战局里的眩晕验证**。
>
> **② 伤害数字改成完整转圈 360°**
> * `rotation = 原值 + θ`（0→360°，一个 `spinPeriod` 转满一圈，**仍与全局周期逐值一致、可对齐音乐**）；
>   v1.5.1 的 `±15°·sin θ` 摆动**已删除**（口径开关留在 `config.js`：`FLAT_ONLY_FULL_TURN`，一行可回滚）。
> * ★ 仍然**不写 `scale.x`**（`axisK ≡ 1`）—— 这一条**不许退**：轴转的 `cos θ` 横向压扁正是撕裂的根源。
> * ★ **观感（如实描述）**：整圈意味着**每个周期里有半圈数字是倒着的**（θ ∈ (90°,270°) 那一段）。
>   服主明确要求"完整转圈"，所以照做；一个默认周期 67 帧 ≈ 1.12 s，而伤害数字寿命 0.9~1.8 s
>   （`public/js/render/fx/numbers.js:14-16`）⇒ 大多数数字一生里会经历"正 → 侧 → 倒 → 侧 → 正"。
>
> ★ **4 个旋转参数 / 两种模式 / 9 个分组 / 混乱模式 / 界面三档 / 换面开关 + 死区 / `PREF_V = 7` 一个字节未改**，
> 设置栏**没有新控件**。
>
> ★★ **v1.5.1（上一版）是服主的小修：伤害数字恒为平面旋转（防撕裂），不受全局旋转档影响。**
> 服主原话：「测试发现**伤害数字中轴旋转会出现撕裂现象**，将**伤害数字旋转单独改为平面旋转**。」
> * **根因**：'绕竖直轴'档在 2D 里只能靠 `scale.x = 原值 × cos θ` 表达 —— 那是把**整张位图连同字形**横向压扁。
>   伤害数字是 24 px 的 `BitmapText`，压到零点几倍宽时一个笔画只剩两三个像素
>   （抗锯齿采样率 < 1 采样/像素）⇒ 笔画明暗随机化 ⇒ **撕裂 / 毛边 / 闪烁**（越接近侧面越明显）。

>   **写 `rotation = ±15° · sin θ`**（周期仍取全局 `spinPeriod`）。竖向压缩与横向补偿**照旧**。
> * ★ **只恢复"判据"，不恢复 v1.1.0 的那两个专用参数**（`numSpinHz` / `numAmp`）：4 参数口径一个字节不动，
>   面板**没有新控件**；`PREF_V` 仍是 **7**。
> * ★ **其它分组（`fx` / 单位 / 装置 / 血条 / DOM）照旧跟随全局档**，一个字节都没改。
>
> ★★ **v1.5.0（上一版）是服主的新需求「转身换面（正/背）」**：绕竖直轴转到**侧面（投影宽度过零）**那一刻把模型从

> **倒地 / 死亡 / 替身 / 备战盘一律不碰**；换面**只换模型**，sim 侧朝向与战斗状态**一字未变**。

## 1. 参数表（v1.6.0：还是只有 4 个旋转参数；两个周期是**输入式**；另有换面开关 + 换面死区）

| 面板名字 | 键 | 单位 | 范围 | 默认 | 步进 | 控件 | 换算 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **水平旋转速度** | `spinPeriod` | **帧**（60 fps） | 6 – 600 | **67** | 1 帧 | ★**整数帧输入框** | 秒 = 帧 ÷ 60（67 帧 ≈ 1.117 s/圈） |
| **压缩周期** | `squashPeriod` | **帧**（60 fps） | 6 – 600 | **38** | 1 帧 | ★**整数帧输入框** | 秒 = 帧 ÷ 60（38 帧 ≈ 0.633 s/次） |
| **压缩强度** | `squashMinPct` | **%**（最低时的高度 / 原高） | 25 – 75 | **60** | 1 % | 滑块 | 最低点 `scaleY = squashMinPct / 100` |
| **横向补偿** | `widthMaxPct` | **%**（最低时的宽度倍率） | 100 – 150 | **110** | 1 % | 滑块 | 最低点 `scaleX = widthMaxPct / 100` |

* ★★ **v1.4.0：两个周期是"输入式"**（服主原话「应该取消滑块设计改为输入式设计，手动调节滑块对齐到帧极为不便」）：
  `<input type="number" min=6 max=600 step=1>` + 我们自己的一套清洗/提交规则（见 §1.2）。
  面板**紧邻**显示「N 帧 ≈ X.XXX s/圈」，**不换行**。
* **「精确到帧」**：帧率基准写死 `FPS = 60`（`client/config.js`）；`sanitize()` 对两个周期做 `Math.round`
  + 夹到 6~600 ⇒ **一律是 6~600 的整数帧**，`NaN` / 空 / 非数字**永远进不了存档**。
  想对齐音乐时按帧数算就是精确的（键入 **127** 生效的就是 **127 帧 = 2.1167 s**）。
* **两种旋转模式共用这 4 个参数**：`spinMode = 'axis'`（绕竖直轴，默认）/ `'flat'`（平面内旋转）。
  差别只有一处 —— 旋转角怎么落地：
  * `'axis'`：**横向乘上 `cos θ`**（只压宽度 + 镜像翻转），**不写 `rotation`**；`θ = 2π·t/Ts`。
  * `'flat'`：**写 `rotation = 原值 + θ`**（整圈），横向不额外压。
  两种模式下压缩（`squashPeriod` / `squashMinPct` / `widthMaxPct`）完全一样。
* ★★ **v1.5.1 / v1.6.0 的唯一例外（是"判据"，不是"第 5 个参数"）**：**`num`（伤害数字 + 浮动标签）恒为平面旋转，
  且是完整一圈 360°（v1.6.0）** ——
  它**不吃 `cos θ`**（横向只留"横向补偿"）、**恒写 `rotation = 原值 + 15°·sin θ`**（周期仍是上面的 `spinPeriod`），
  与全局 `spinMode` **解耦**。理由与实测见 §5.6。**它没有自己的参数**（面板上没有新控件）。
* **没有"倾斜 / 侧向偏移 / 透视"这一类参数**：一个都没有，代码里也没有对应字段（§6）。
* 其它非旋转参数（都不影响"旋转参数只有 4 个"这条）：
  ★★**`fbSwap`（转身换面（正/背），默认 `true` 开）**、★★**`fbDead`（换面死区，0 – 0.30，默认 `0.04`，步进 0.01）**、
  `spinMode`（旋转模式）、★**`domMode`（界面三档 'on' / 'sync' / 'off'，默认 'on'）**、
  `budget`（每帧写入预算，默认 400）、
  `chaos` / `chaosPhi` / `chaosAmp` / `chaosWanderHz`（混乱模式，默认全关 / ±35% / 0.12 Hz）、

### 1.2 ★ 输入式控件的即时生效与清洗策略（v1.4.0）

| 事件 | 行为 |
| --- | --- |
| `input`（每敲一个字符） | 文本 trim 后**非空且是有限数** ⇒ `Math.round` + 夹到 6~600，**立刻写仓库**（不必失焦）；`9999` → **600**、`1` → **6**、`127` → **127** |
| `input`（空串 / `-` / `abc` / `1e`） | **一个字节都不写**（保留上一次的有效值），也**不阻止继续输入**（用户还没输完） |
| `Enter` | 提交 + 把输入框文本按最终有效值回写（清掉 `006` / `127abc` 这类残留） |
| `blur` | 同上（失焦时保证框里显示的就是生效值） |
| `↑` / `↓` | 我们自己处理：当前值 ± 1 帧、夹取、**立刻提交**（不依赖浏览器的原生步进） |
| `Tab` / `Shift+Tab` | **完全不拦**（焦点照常走） |
| `focus` | `select()` 全选 ⇒ 直接键入就是替换旧值 |

### 1.1 数学定义（报告里复算用的就是这三行）

```
s(τ) = (1 − cos(2π·τ / Tq)) / 2            Tq = squashPeriod / 60 秒    s ∈ [0,1]（0 = 原高，1 = 压到最低）
yK   = 1 − (1 − M)·s                       M  = squashMinPct / 100      ⇒ s = 1 时 yK = M
xK   = 1 + (W − 1)·s                       W  = widthMaxPct  / 100      ⇒ s = 1 时 xK = W
θ(τ) = 2π·τ / Ts                           Ts = spinPeriod / 60 秒      ⇒ 一个 Ts 正好一圈
写进容器：scale.x = 原值 × xK × (axis ? cos θ : 1)；scale.y = 原值 × yK；(flat 时) rotation = 原值 + θ
★★ v1.5.1 / v1.6.0 例外（num 分组，永远按"平面内"这一支算；★ v1.6.0：角度是**整圈**而不是 ±15° 摆动）：
           scale.x = 原值 × xK           （**没有 cos θ 这一项** ⇒ 横向永不被旋转压到过零）
           rotation = 原值 + 15° · sin θ （摆角有界；θ = 0/180° 时恰好为 0 ⇒ 正对/背对镜头时数字是正的）
```

## 2. 老存档怎么换算（向后兼容）

`load()` / `sanitize()` 会认老键并**换算**成新键，而且**只在新键缺省时才用老值**
（⇒ 幂等：一旦用户在新版里改过滑块，老键就再也不会覆盖它）。

| 老键（v1.2.1 及更早） | 换算成 | 公式 | 老默认值 → 新默认值 |
| --- | --- | --- | --- |
| 压缩速度（Hz） | `squashPeriod` | `round(60 / Hz)` 帧 | 1.6 Hz → **38 帧** |
| 水平旋转速度（圈/秒） | `spinPeriod` | `round(60 / Hz)` 帧 | 0.9 圈/秒 → **67 帧** |
| 压缩强度（`scale.y` 振幅） | `squashMinPct` | `round((1 − 振幅) × 100)` %，夹 25–75 | 0.22 → 78 % → **夹到 75 %** |
| 横向补偿（反比系数） | `widthMaxPct` | `round(100 × (1 + 补偿 × 振幅))` %，夹 100–150 | 0.35 × 0.22 → **108 %** |
| 数字旋转 / 数字压缩 | **不换算** | 伤害数字分组**仍然没有自己的参数**（服主规格：所有单位的旋转只有 4 个参数）。★ v1.5.1 补注：它的**旋转判据**恒为平面内（§5.6），但这**不是**一个参数 | — |
| 界面角度（°） | **删除** | 角度上限变成内部常量 `DOM_MAX_DEG = 60`（不再是用户参数）；★ v1.4.0：`domDeg > 0 → domMode='on'`、`domDeg = 0 → domMode='sync'` | 60° → **'on'** |
| 界面旋转开关 `domSpin`（v1.3.0 的布尔） | **`domMode`（三档）** | `true → 'on'`、`false → 'sync'`（老的"仅上下浮动"档就是新「同步」档） | `true` → **'on'** |
| 转身透视（透视斜切系数） | **删除** | 本版不再有任何斜切 / 透视（连字段都不存在） | — |
| `Hz = 0`（老版"不转"） | 周期取最长 | `600 帧`（10 s，主观上几乎静止） | — |

* ★ **老的总开关 `on`、9 个分组开关、混乱模式四个参数一律原样保留**（缺的键按默认补，不会崩、不丢 `on`）。
* ★ 存储外壳仍然"多种都认"：`{v:N,cfg:{…}}` 与"裸配置对象"都能读（**先看有没有 `cfg` 字段**，不比对版本号）。
* 换算表可执行版本：`legacyConvert()`（`client/config.js` 导出，验收脚本直接调它复算对照），
  旧键的**字面键名**在 `<开发期报告>/29-dj-reparam.md` §2 的对照表里。

### 3.1 "战斗中"的判据

### 3.2 "以最小单位绕自身中心旋转"

* 每个被标记的元素都写死 `transform-origin: 50% 50%` ⇒ 绕**自己的几何中心**转（竖直轴模式 = 绕自身中轴）
  ⇒ 本体中心点不动、可点击区域不偏移（实测整周期中心漂移 ≤ 1 px）。
* 标记规则是「**最小单位优先**」：某个候选元素的**后代里还有候选** ⇒ 它是容器 ⇒ **不标记**
  （统计字段 `containers`）。**容器一律不转**，所以父子旋转**不会叠加**：
  每个真正动起来的元素的实际角度就是它自己的 `|θ| ≤ 60°`（验收里逐元素断言 `withMarkedAncestor === 0`）。

## 4. 两个周期各自独立：为什么用 `@property` + 两条动画

CSS 里"旋转"与"压缩"抢同一条 `transform`；一条 keyframes 服务两个周期就只能取两者的**最小公倍数**
（帧数一大就退化成抽搐，而且不精确）。所以 v1.3.0（v1.4.0 沿用）：

```css
@property --sp-dj-r  { syntax:"<angle>";  inherits:false; initial-value:0deg }
@property --sp-dj-sx { syntax:"<number>"; inherits:false; initial-value:1 }
@property --sp-dj-sy { syntax:"<number>"; inherits:false; initial-value:1 }

@keyframes sp-dj-r { … --sp-dj-r: θ(u) 的 8 个正弦采样 … }         /* 时长 = spinPeriod/60 秒 */
@keyframes sp-dj-q { … --sp-dj-sx / --sp-dj-sy 的 8 个余弦采样 … } /* 时长 = squashPeriod/60 秒 */

html.sp-dj-dom <每个目标>.sp-dj-mark{
  transform-origin:50% 50%;
  transform:rotateY(var(--sp-dj-r)) scale(var(--sp-dj-sx),var(--sp-dj-sy));   /* 'flat' 模式是 rotate(...) */
  animation:sp-dj-r <spinPeriod/60>s linear infinite, sp-dj-q <squashPeriod/60>s linear infinite;
}
```

* 两条动画驱动**不同的属性** ⇒ 周期互不影响，各自**精确到帧**。
* `inherits:false` ⇒ 自定义属性不会渗到子元素（配合"容器不转"更安全）。
* 兼容性：`@property` 自 **Chrome 85 / Edge 85 / Safari 16.4** 起可用
  （实测本机 Chrome 99 与 Edge 154 都正常插值）。选它而不选"独立 `rotate:` / `scale:` 属性"
  （Chrome 104+）就是因为**兼容面更宽**。
* **没有** perspective / 斜切 / translate / matrix；`transform` 只有 `rotateY`（或 `rotate`）与 `scale`。
  ★ v1.4.0：**「同步」档不注册 `--sp-dj-r`、不生成旋转 keyframes、不写 `rotateY`**，
  `transform` 只剩 `scale(var(--sp-dj-sx),var(--sp-dj-sy))`、`animation` 只剩 `sp-dj-q` 那一条。
* `animation-delay` 是**每个元素一份**的确定性负延迟（旋转与压缩各用各的分数相位；开混乱时最多再加
  `chaosPhi` 个周期的偏移）—— **只平移时间轴，不改时长 ⇒ 周期不变**。
  ★ v1.4.0「同步」档：**所有元素都写 `0s`**（逐字符一致）+ 回显 `--sp-dj-phase: 0.000000`。

## 5.6 ★★ v1.5.1 / v1.6.0：伤害数字恒为平面旋转（防撕裂）· 角度 = 完整一圈 360°

**服主原话**：「目前测试换面功能无问题。测试发现**伤害数字中轴旋转会出现撕裂现象**，
将**伤害数字旋转单独改为平面旋转**。」

### 5.6.1 撕裂的根因（几何 + 采样，两句话）

1. **`'axis'`（绕竖直轴）档在 2D 里唯一的表达方式是横向压扁**：`scale.x = 原值 × cos θ`。
   它压的**不是"文字的位置"而是整张位图连同字形**。
2. 伤害数字是 **24 px 的 `BitmapText`**（`public/js/render/fx/numbers.js:289`；屏幕上还会再乘一个
   `clamp(s/115, 0.42, 1.05)` 的缩放，`numbers.js:39`）。`cos θ` 走到 0.1 附近时，
   一个字形只剩 **2~3 个像素**，笔画的抗锯齿采样率 < 1 采样/像素 ⇒ 每个笔画的覆盖度变成**随机采样**
   ⇒ 笔画明暗抖动 ⇒ 看上去就是**撕裂 / 毛边 / 闪烁**（越接近侧面越明显，过零那一两帧几乎完全读不出来）。

文字的唯一用途就是"读" ⇒ 这一组**必须恒为平面内旋转**。

### 5.6.2 只恢复"判据"，不恢复旧参数

| | v1.1.0（曾经的保护） | v1.3.0 ~ v1.5.0（保护被删掉） | **v1.5.1（本次修复）** |
| --- | --- | --- | --- |
| `num` 的旋转 | **强制平面内** | 跟随全局 `spinMode` ⇒ 轴档下被压扁 ⇒ **撕裂** | **强制平面内**（恢复） |
| 专用参数 | `numSpinHz` / `numAmp`（两个滑块） | 无 | **无**（不恢复；4 参数口径不动） |
| 面板控件 | +2 个 | 0 | **0**（服主没有要求新控件） |
| 周期来源 | 自己的 `numSpinHz` | 全局 `spinPeriod` | 全局 `spinPeriod`（沿用） |

### 5.6.3 ★★ v1.6.0：角度改成**完整一圈 360°**（v1.5.1 的 ±15° 摆动已删除）

**服主原话**：「**伤害数字水平旋转是应该做成能够完整的转圈，而非仅是限定角度晃动**。」

```
rotation = 原值 + flatOnlyTheta(θ)          θ = 2π·τ / spinPeriod
flatOnlyTheta(θ) = θ                        （FLAT_ONLY_MAX_DEG = 360 ⇒ 整圈）
```

* **周期与全局逐值相同**（共用同一个 θ ⇒ 同一个 `spinPeriod`，"跟着节奏走 / 可对齐音乐"照旧）；
* **单调递增**（θ 只增不减 ⇒ 始终同向转，不再折返）；
* **仍然不写 `scale.x`**：`axisK ≡ 1` ⇒ `scale.x = 原值 × xK`，横向只走"横向补偿"（默认 100%→110%），
  **绝不因旋转过零** —— 这一条是 v1.5.1 立的规矩，v1.6.0 **不许退**；
* **观感（如实描述，不粉饰）**：一个周期里 **≈ 一半时间数字是倒着的**（θ ∈ (90°, 270°)）。
  服主明确要求"完整转圈"，所以照做；`FxNumbers` 的伤害数字寿命 0.9~1.8 s（`numbers.js:14-16`），
  默认周期 67 帧 ≈ 1.12 s ⇒ 大多数数字一生里会经历"正 → 侧 → 倒 → 侧 → 正"。
  ★ 报告 §③ 里给了整周期轨迹（min/max/跨度）与 6 个定格相位（0/60/120/180/240/300°）的截图。
* **口径开关**：`config.js` 的 `FLAT_ONLY_FULL_TURN`（true = 整圈 360°，false = 回到 v1.5.1 的 ±15° 摆动，一行回滚）；
  `limits().flatMode` 回显 `'cycle'` / `'swing'`，`limits().flatMaxDeg` = 360 / 15。

### 5.6.3b 历史：v1.5.1 的角度为什么曾经是 ±15°

`'flat'` 档对普通目标的角度策略是 `rotation = θ`（一个 `spinPeriod` 转满 360°）。
对小人 / 特效没问题，但**文字转过 90° 就竖着、过半圈还是倒的**，而伤害数字只活 0.9~1.8 s
（`numbers.js:14-16`）——"倒着的数字"等于没有。所以这一组取**有界摆动**：

```
rotation = 原值 + FLAT_ONLY_MAX_DEG · sin θ        FLAT_ONLY_MAX_DEG = 15°
```

* **周期与全局逐值相同**（共用同一个 θ ⇒ 同一个 `spinPeriod`，"跟着节奏走"的观感不变）；
* **有界** ⇒ 任何相位都读得出来（15° 是"看得出在转、又完全不费眼"的档位）；
* `θ = 0° / 180°`（正对 / 背对镜头）时摆角**恰好 0** ⇒ 最该清晰的相位上数字是正的。

★ 这是一个**代码内的具名常量**（`client/config.js` 的 `FLAT_ONLY_MAX_DEG`），改它是一行；
之所以**不做成滑块**：服主只要求"改成平面旋转"，没有要求给它一个旋钮（4 参数口径也不该被打破）。

### 5.6.4 与全局档解耦（"不叠加、不双倍转"）—— v1.6.0 照旧

`client/engine.js` 的 `applyTarget()` 里只有两行判据（`flatOnly = isFlatOnlyGroup(gid)`）：

```js
const axis = ctx.axis && !flatOnly;                  // ① 白名单里的组永远按"平面内"这一支算
const axisK = axis ? ctx.axisK * sgn : 1;            //    ⇒ 横向恒为 1（不含 cos θ）
o.rotation = axis ? s.rot : s.rot + (flatOnly ? flatOnlyTheta(ctx.theta) : ctx.theta);   // ② 恒写 rotation
```

| 全局 `spinMode` | `num` 的 `scale.x` | `num` 的 `rotation` | 其它分组（`fx` / 单位 / …） |
| --- | --- | --- | --- |
| `'axis'` | `原值 × xK`（**无 `cos θ`**，区间 `[原值, 原值×W]`） | `原值 + 15°·sin θ` | 照旧：`scale.x ∝ cos θ`（会过零、会镜像） |
| `'flat'` | 同上（**逐值相同**） | 同上（**逐值相同**） | `rotation = 原值 + θ`（整圈） |

★ "逐值相同"是断言、不是口号：报告 32 §数值对照 给出两档下同一批相位的逐帧数值（`num` 完全一致）。

### 5.6.5 明确**没有**做的事

* `fx` 分组**照旧跟随全局档**（粒子 / 弹道 / 地面环 / 光环 / 喷火 / 锁定环 / 区域）。
  ★ 已逐句柄复核：`fx` 的抓手**没有任何文字类目标**（`targets.js` 的 `collectFx` 里全是 Sprite / Graphics / Mesh），
  浮动标签 `fx.labels[]` 本来就归 `num` 组 ⇒ **不需要**扩大白名单（任务口径：先报告再动）。
* `fx.pops`（升格 / 入场提示里的 `BitmapText`，`arrivals.js:95`）**不在任何分组里**，
  本 Mod 从不写它 ⇒ 既不会被压扁、也不参与本 Mod 效果（§13 按"未覆盖"列出）。
* DOM 界面**没动**：它走 CSS `rotateY`（≤60°），是**浏览器对 HTML 文字做变换**（不是位图压扁），不存在同一撕裂机制。

## 5.5 ★★ v1.5.0：转身换面（正/背）

**服主原话**：「注意到干员的 spine 有**正面和背面**两种状态，能不能用**旋转宽度到达 0 像素宽度时切换正背面
spine** 来实现**更真实的旋转效果**？」⇒ 就是：绕竖直轴转到**侧面（投影宽度过零）**那一刻把模型从正面换成背面、
过了 180° 再换回来。观感从"原地压扁成一张纸"变成"**真的转过身去**"。

实现全在 `client/frontback.js`（约 300 行，含全部"为什么"的出处注释）。

### 5.5.1 用的是宿主现成的原语（`public/**` 一行都没改）

`public/js/render/units.js` 抬头注释（`:21-26`）逐字写着：

> …the **Back model for UP** (when one exists, research 07 §5.5), the Front model for RIGHT and DOWN, mirrored for
> LEFT; … **`setDir(dir)` re-orients a live view (swapping Front ⇄ Back without a fallback flash)**.

所以本功能只需要两句话：

| 想要 | 调用 | 宿主内部行为 |
| --- | --- | --- |
| **背面** | `view.setDir('UP')` | `_wantsBack()` 为真（`dir === 'UP'` 且 `hasBack(id)` 且"站着，或该 Back 骨架自带 Die 剪辑"）⇒ `_syncModel()` → `_loadSpine()` → 加载 Back 骨架 |
| **正面** | `view.setDir(其它任意方向)` | `dir !== 'UP'` ⇒ `_wantsBack()` 必为假 ⇒ 加载 Front 骨架 |

换面走 `_acquireSpine` 的 **swap 分支**（`units.js:576-581`）：**在原地替换模型、中间不闪 fallback 钻石**，
旧模型正在演的 fall / deploy 进度还会接着演。

### 5.5.2 判据与死区

* **判据**：当前 `cos θ` 的符号 —— 这正是"投影宽度过零"的数学形式（引擎写进 `scale.x` 的轴转乘数就是 `cos θ`）：
  `cos θ > 0` ⇒ 正面；`cos θ < 0` ⇒ 背面。
* **只在绕竖直轴档生效**：`spinMode === 'flat'`（平面内旋转）时 `axisK ≡ 1`、宽度不过零 ⇒ **不换面**。
* **死区（迟滞）** `fbDead`（默认 **0.04**，可调 0 – 0.30）：
  * 正面 → 背面：要 `cos θ < −fbDead`；
  * 背面 → 正面：要 `cos θ > +fbDead`；
  * `|cos θ| ≤ fbDead` 这条死区里**保持上一次的判定**。
  * 0.04 ≈ **90° ± 2.29°**（一个周期 1.3% 的时间）。★ 它比默认周期 67 帧**一帧**的 `|Δcos θ| ≈ 0.094` 还小
    ⇒ 死区**不会**把换面额外推后一帧：换面永远发生在**过零后的第一帧**（"最接近 0 宽"的可达帧）。
  * 相位在本引擎里是**单调递增**的（`phase += dt`，混乱模式只加**固定**相位偏移 `dPhi`，不抖）⇒ 死区只用于
    防御"掉帧 / −0 符号 / 浮点边界"这一类意外，不会吃掉正常周期。
* **换面次数**：一个旋转周期里 `cos θ` 的符号变 **2** 次 ⇒ **每个周期恰好换面 2 次**（正→背 1 次、背→正 1 次），
  实测见报告 §每周期换面次数（合成 + 真机各一份）。

### 5.5.3 背面资产为什么用 `|cos θ|`

v1.4.0 的写法是 `scale.x = 原值 × xK × cos θ` —— `cos θ < 0` 时**横向镜像**。这对"只有正面一张图"的单位是
**正确**的（平面卡片翻到背面，看到的就是正面的镜像）。但换上真的背面骨骼之后，**背面资产本身已经是
"转过 180° 的那张图"**（角色背对我们 ⇒ 角色的右手在屏幕右侧），再镜像一次就成了"**背面的镜像**"：

| θ | v1.4.0（只有正面） | v1.5.0（换成背面之后） |
| --- | --- | --- |
| 0° | 正面，完整宽 | 正面，完整宽 |
| 90° | 压成 0 宽 | 压成 0 宽（**换面就在这一刻**） |
| 180° | **镜像的正面**（角色右手仍在屏幕左侧 ⇒ 像卡片翻面） | **背面**（角色右手在屏幕右侧 ⇒ 像人转过身） |

⇒ 屏幕上是背面资产时（`entryBack === true` 且该视图由本功能管理）横向取 **`|cos θ|`**。
★ 功能关掉、或该单位不在本功能的管辖内时，**逐值回到带符号的 `cos θ`**（v1.4.0 行为，字节级相同）。

### 5.5.4 安全边界（哪些情况**一个字节都不写**）· ★★ v1.6.0 新增"晕眩 / 冻结 / 沉睡"

| 情况 | 判据 | 为什么 |
| --- | --- | --- |
| **没有背面模型** | 宿主自己的 `view.ctx.assets.hasBack(id)`（`id = info.spine \|\| info.defId`，与 `_wantsBack()` 逐字相同） | 不猜路径；拿不到 assets / hasBack 时 fail-safe（返回 false） |
| **倒地 / 死亡 / 淡出** | `alive === false` / `dying > 0` / `down` 非空 | ★★ `_wantsBack()` = `alive \|\| Die 剪辑时长 > 0`：**135 个 Back 骨架里只有 4 个自带 Die 剪辑**，其余 131 个必须退回 Front 播死亡（GitHub issue #25：否则背面会顶着攻击循环躺在换人环下面）。⇒ 这三种状态下**把 `dir` 留在原处**，一个字都不写，把决定权**完全留给宿主** |
| **替身 / 形态** | `view.form` 非空 | 形态是一套 clip 集（`FORMS`），front/back 两套骨架的 clip 未必成对 |
| **备战盘 / 侦察盘 / 预览栏 / 首领** | `view.prep === true` | 那里的 `dir` 就是**玩家正在编辑的部署方向本身**，且 `app.js:772` 每次备战状态同步都会 `v.setDir(info.dir)` 重设 ⇒ 插手只会两侧互抢 |
| **敌人** | `isEnemy` | `setDir()` 对敌人本来就是 no-op（`units.js:793`），`_wantsBack()` 对敌人恒假 |
| 开关关 / 平面内档 / 分组关 / 卸载 | `fbGate(cfg)` / 分组开关 / `dispose()` | 走 `fb.restoreAll()` / `fb.restoreGroup(gid)`：`dir` 与三个朝向指示字段**逐值还原** |

★ 还有一种情况说明一下：宿主的 `UP` 本来就是"背面"。所以对一个**部署时就朝上**的干员（`dir === 'UP'`，
宿主本来就在显示背面），本功能在"正面半周期"里会把它临时调成 `RIGHT`（= 正面），过了 180° 再调回 `UP`；
`fbDead` 与"宿主原值"会保证退出时逐值还原。

### 5.5.5 换面**只换模型**

`setDir()` 顺手会写四个字段（`units.js:796-800`）：`dir`（我们要的）、`facing`、`visFacing`、`hasDir`。
后三个不是"模型"而是**朝向指示**，本功能每次 `setDir()` 之后**逐值还原**：

| 字段 | 谁在读 | 本功能的处理 |
| --- | --- | --- |
| `dir` | `units.js:1098` 地面那个橙色 › 的方向 | 换面期间被我们覆盖 ⇒ 见下一行 |
| `hasDir` | `units.js:1087` 要不要画那个 › | **只在我们真的覆盖了 `dir` 期间**压成 `false`；`dir` 一回到宿主原值就还原成宿主原值 |
| `facing` / `visFacing` | `units.js:1024` 模型镜像、`units.js:1233-1234` **阻挡标记**画在哪一侧 | 每次 `setDir()` 之后立刻逐值还原 ⇒ 阻挡标记不会跳到另一侧 |

⇒ 换面期间**没有**朝向指示在 90°/180° 之间来回跳（那会把"部署 / 攻击方向"这条**玩法信息**说错），
而功能一关 / 卸载 / 视图换代就**逐值还原**。

### 5.5.6 不碰玩法

* `setDir` 是**渲染层**方法：它只写 `view.dir` / `view.info.dir` / `view.facing` / `view.visFacing` /
  `view.hasDir` / `view.imp.dirty`，然后请求换模型；**不写任何 sim 状态、不发任何网络请求**。
* `view.info` 是 `render/app/info.js:25-53` 里**新建的对象字面量**（`renderInfo()`）⇒ 它**不是** sim 的对象，
  `info.dir = 'UP'` 改的是渲染侧副本。
* 全库只有 `render/units.js` 自己读 `view.info.dir`（第 405 / 1087 / 1098 行）；`view.dir` 也只有
  `units.js:775`（`_wantsBack`）与 `:1098`（地面 ›）在读。**没有任何玩法逻辑读它们**。
* 真机证据（调用 `setDir` 前后 sim 状态逐值比对）见报告 `31-dj-frontback.md` §不碰玩法。

## 6. "没有倾斜 / 没有侧向偏移"是怎么被机械保证的

1. **代码层面**：整个 Mod 目录里那个表示"斜切"的字段名**一次都不出现**（`grep -r` 零命中）
   —— 既没有读、也没有写（验收报告 §2 有完整字符串证据）。
2. **写入层面**：每帧只写两处
   * `o.scale.set(s.sx * xK * axisK × 换面符号, s.sy * yK)`（`scale.x` / `scale.y`）；
     换面符号在**功能关掉时恒为 `+1`** ⇒ 与 v1.4.0 逐值相同；开着时它是 `−1` **当且仅当屏幕上挂的是背面资产**
     （⇒ 横向用 `|cos θ|`，见 §5.5.3）—— 它仍然**只是一个正负号**，不引入任何新的几何量；
   * `'flat'` 模式下 `o.rotation = 原值 + θ`（`'axis'` 模式**不写** `rotation`）。
   除此之外只会在"几何画在屏幕绝对坐标里的 Graphics/Mesh"（`device` / `hud` 两组）上写
   `pivot` + `position` = **该对象自己的屏幕锚点**（不写它就会被甩到画布角落；这也不是"侧向偏移"，
   而是把变换原点搬回物体自己身上）。
   ★ v1.5.0 的换面**不写任何 PIXI 字段**：它只调宿主现成的 `view.setDir()`（§5.5）。
3. **"原地"**：`body.position` / `body.pivot` 在整个采样窗口里**逐值不变**，且与"关掉 Mod"时逐值相同
   （真机实测漂移 = 0）。旋转是"绕单位自己的竖直中轴"：`body` 的子节点都以脚底点 `(0,0)` 为局部原点且左右对称
   ⇒ `scale.x` 就是绕 `x = 0` 这条竖直线缩放。
4. **DOM 层面**：只有 `rotateY/rotate` + `scale`，没有 perspective / translate / matrix；
   `transform-origin` 写死 `50% 50%`。

## 7. 混乱模式（chaos）

服主口径：「开启时**所有可旋转目标**都会有随机的时间偏移 + 压缩程度在设定值附近活动，但**仍保证周期与设定值相同**」。

* **相位偏移**：每个目标一个确定性的 φ ∈ [−1, 1]（按 `name`/`uid` 散列播种），实际偏移 = `φ × chaosPhi × 自己的周期`。
  只进 `sin/cos` 的**相位**，**频率一个字节都没改** ⇒ 零交叉间隔与未开混乱时逐点相同。
* **幅度游走**：`factor = 1 + chaosAmp/2 · inst + chaosAmp/2 · wander`，`inst` 是该目标的固定随机量、
  `wander` 是双正弦低频游走 ⇒ `|factor − 1| ≤ chaosAmp`，永不越界。
  ★ v1.3.0：这个幅度因子**同时**乘在**压缩强度（`1 − M`）与横向补偿（`W − 1`）**上
  —— 只缩放其中一个会变成"压扁了却不横向摊开"（像被裁掉，不像被压）。压缩深度上限夹在 0.95（永不出现 0 高度）。
* 状态按**目标对象**记（`WeakMap`）⇒ 目标销毁自动回收；播种确定性 ⇒ 关掉再打开逐点一模一样。
* **DOM 组的混乱只覆盖时间偏移，不覆盖幅度**（一条 keyframes 服务所有元素，逐元素幅度要逐元素生成 keyframes，不值当）。

## 13. 未做 / 已知偏差（如实列）

★★ **v1.6.0 新增的三条**（其余条目是 v1.5.1 及以前就有的，原文保留在下面）：
1. **晕眩修复未经真实战局的眩晕验证**：本轮**未能自然造出晕眩**（试过的路径见报告 §①）。

2. **强控期间的"正 / 背"可能与 `cos θ` 的符号不一致**（最多偏一个 ±90° 窗口）：这是"绝不碰"的必然代价，

3. **整圈下每个周期有 ≈ 半圈数字是倒着的**：服主明确要求"完整转圈"，所以照做 ——
   如果实际观感不可接受，回滚只要一行（`config.js` 的 `FLAT_ONLY_FULL_TURN = false` ⇒ 回到 ±15° 摆动）。

1. **3D 底盘（board3d）下的装置箱体**：句柄被 `scene.createDevice` 的闭包藏着（`h.mesh` 恒 `null`），

2. **光束（`fx.beams`）不做**：它每帧用 `moveTo/lineTo` 以屏幕绝对坐标重画几何，容器上没有可旋转的局部坐标系。
3. **DOM 组的混乱不覆盖幅度**（只覆盖时间偏移）：理由见 §7。
4. **impostor 路径的大体型敌人**：若官方骨架原点不在包围盒横向中点，轴线的横向偏差 = 包围盒中心偏移
   （局部几十像素，按屏幕缩放后几个像素）。**不做补偿**（补偿 = 主动位移，违反"原地"）。
5. **`@property` 注册无法撤销**（见 §10 末）；老浏览器（Chrome < 85）不支持时 DOM 组会整体不生效
   （PIXI 组不受影响；本机 Chrome 99 / Edge 154 实测正常）。
6. 老键「数字旋转 / 数字压缩」**不再有对应参数**（并入统一 4 参数），见 §2。
   ★ v1.5.1：伤害数字的**旋转判据**已恢复为"恒平面内"（§5.6），但**仍然没有**给它的可调参数。
6.1 ★★ v1.5.1 的**明确不扩面**（任务口径："先报告再动"）：
   * `fx` 分组**照旧跟随全局档**。逐句柄复核过：`collectFx` 里的抓手全是 Sprite / Graphics / Mesh，
     **没有任何文字类目标**（浮动标签 `fx.labels[]` 本来就在 `num` 组里）⇒ 无需扩面。
   * `fx.pops`（升格 / 入场提示的 `BitmapText`，`arrivals.js:95`）**不在任何分组里** ⇒ 我们从不写它：
     它既不会被压扁（**没有撕裂风险**），也不参与本 Mod 效果。**未覆盖**（与 v1.2.1 起一直如此）。
   * `hud` 组里的文字（血条/SP 条上的数字，`units.js:1320` 的 `P.Text`）**照旧跟随全局档** ——
     它们是屏幕绝对坐标下的小字号文本，属于任务口径里的"其它分组照旧"（未额外保护）。**未改**。
7. ★★ v1.5.0 换面的**已知边界**（如实列）：
   * **换面可见的那一帧有 1 帧延迟**：`setDir()` → `_syncModel()` → `assets.spine.acquire()` 是异步的
     （`.then` 走 microtask，本帧的渲染仍在同一帧里先画旧模型）⇒ 真正看到背面是**下一帧**。
     所以"过零处 |scale.x|"的实测值 ≈ 一帧的 `|Δcos θ|`（默认 67 帧周期 ≈ 0.09 ~ 0.19）。
     ★ 这**不是**"背面突然以完整宽度出现"：换面判据本身就要求 `|cos θ|` 先越过死区（默认 0.04），
     而且换面发生在过零后的第一帧 —— 报告 31 给出逐帧数值。
   * **换面期间模型会重建**：每次换面都会新建一个 `SpineActor`（宿主自己的 swap 路径）。一个旋转周期每单位 2 次，
     战斗里 10 个干员 ≈ 每秒 18 次；长周期（600 帧）时约每秒 2 次。★ 实测单帧耗时与页面异常见报告 31；
     若低端机觉得吃力，把**旋转周期调长**或**关掉「转身换面」**即可（都可以在面板里实时切）。
   * **`dir` 是"宿主的原值"只在第一次接管时记录**：如果某个视图**在我们管辖期间**被宿主合法地改了 `dir`
     （目前只有备战盘会这样，而备战盘被排除在外），本功能会按 `restoreGroup`/`restoreAll` 的路径还原到
     "第一次接管时的值"。战斗视图的 `dir` 由 spawn 时的 UnitInfo 固定，不受影响。
   * **部署方向为 UP 的干员**（宿主本来就在显示背面）：正面半周期里本功能会把它临时调成 `RIGHT`
     （否则 `_wantsBack()` 恒真、模型根本不会换），退出时逐值还原。`dir` 自身不是玩法输入（见 §5.5.6）。
